## 1. Agent 架构

```
workflow-engine 内 Agent 编排层
  ┌─────────────┐
  │ 任务规划 Agent │ → 解析输入快照，规划分析步骤
  ├─────────────┤
  │ 病历一致性 Agent│ ┌─ 并行 ─┐
  ├─────────────┤ │        │→ 诊断/用药/检验/过敏交叉核验
  │ 指南合规 Agent  │ └────────┘
  ├─────────────┤
  │  自检 Agent    │ → 去重、严重度调整、低证据抑制
  ├─────────────┤
  │ 审核编排 Agent  │ → 收集人工决定，驱动状态转移
  └─────────────┘
```

| Agent | 职责 | 输入 | 输出 | 需求依据 |
|-------|------|------|------|----------|
| **任务规划** | 解析快照字段，生成分析步骤 DAG | FHIR 快照 | 步骤计划 + 工具调用列表 | §3 工作流第3行 |
| **病历一致性** | 交叉核验诊断/用药/检验/过敏一致性 | 快照字段子集 | 一致性风险项 + 证据坐标 | §3 工作流第5行 |
| **指南合规** | 检索知识库，对照片中指南/院内 SOP | 快照 + 检索结果 | 合规偏差项 + 引用 `chunk_id` | §3 工作流第5行 |
| **自检** | 去重、严重度校准、低证据项抑制、JSON Schema 校验 | 前两 Agent 输出 | 最终风险项列表 | §3 工作流第6行 |
| **审核编排** | 收集人工确认/驳回/升级，驱动状态转移 | 人工决策 | 状态转移 + 任务草稿 | §3 工作流第7-8行 |

**参考 PoC：** PoC 的确定性规则分析（`riskItems`/`conflictRisk` 硬编码 → `_MOCK_RISKS`）→ 由 LLM Agent 替换分析逻辑，保留相同的 `RiskItem` Schema 输出格式。

## 2. LLM 安全边界

| 原则 | 机制 | 需求依据 |
|------|------|----------|
| **LLM 只读** | Agent 不得直接写 DB；输出经 Pydantic v2 校验后由服务端写入 | 架构 P5 |
| **脱敏输入** | Agent 仅接收脱敏 FHIR 快照，不接收原始病历全文 | 架构 §7 |
| **source_type 溯源** | 每条 Agent 输出标注来源类型：`rule`/`retrieval`/`llm`/`manual` | 需求 §8.3 |
| **source_none 降级** | 无知识库引用时标记 `source_none`，禁止生成确定性结论 | PoC 状态机不变量3 |

## 4. 模型路由

| 任务类型 | 模型等级 | 示例 |
|----------|----------|------|
| 分类/抽取 | 轻量（本地 BERT/蒸馏模型） | 字段类型识别、严重度分级 |
| 生成/推理 | 强模型（GPT-4o/DeepSeek/本地 Llama） | 病历一致性分析、指南合规判断 |
| 自检/校验 | 轻量 + Pydantic Schema | 输出 JSON 结构校验 |
