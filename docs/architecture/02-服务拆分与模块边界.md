# 02 — 服务拆分与模块边界

> **基线版本**：v0.2 | **依赖**：00-系统架构总览 §2、01-数据模型 §2、03-接口契约

## 1. 服务边界（顶层拆分）

服务拆分已在 **00-系统架构总览 §2** 中完整定义。此处补充模块级边界和通信约束。

| 服务 | 内部模块 | 数据所有权 | 对外接口 |
|---|---|---|---|
| **workflow-engine** | state_machine / routes.cases / routes.hooks / models / schemas | cases / risk_items / task_drafts / audit_events / review_decisions | REST :8100 |
| **knowledge-orchestrator** | state_machine / routes.documents / routes.search / routes.admin / retrieval / hooks / models / schemas | knowledge_documents / knowledge_chunks / knowledge_ingestion_jobs / knowledge_citations / knowledge_lifecycle_events | REST :8200 |
| **fhir-adapter** | 待建 | patients / encounters / conditions / observations / medication_requests / care_plans / consents / fhir_audit_events | REST :8300 |
| **api-gateway** | 待建 | 无（纯路由层） | REST :8000 |

## 2. 服务间通信约束

- **协议**：HTTP REST（阶段 0），后续可升级 gRPC
- **同步调用**：workflow-engine → knowledge-orchestrator 检索（analyse 阶段）
- **异步回调**：knowledge-orchestrator → workflow-engine 反向阻断（`POST /hooks/knowledge-changed`）
- **统一响应**：所有服务使用 `{"request_id":"...","data":{},"error":null}`（参考 03-接口契约）
- **request_id 透传**：api-gateway 生成 → 注入请求头 → 所有服务透传 → 日志关联

## 3. 各服务模块内边界

### workflow-engine
```
state_machine.py  ← 状态转移唯一入口，依赖 zhenhu-contracts
routes/cases.py   ← 10 端点，不直接操作 ORM，通过 state_machine 代理
routes/hooks.py   ← 接收外部 hook（knowledge-changed），通过 state_machine 代理
models.py          ← SQLAlchemy ORM 定义
schemas.py         ← Pydantic 请求/响应
```

**规则**：路由层不直接写数据库——所有写操作通过 `state_machine` 方法，状态转移前必须经 `assert_case_transition` 校验。

### knowledge-orchestrator
```
state_machine.py  ← 知识版本状态转移唯一入口
routes/documents.py ← 导入/列表/生命周期
routes/search.py     ← 混合检索
routes/admin.py      ← 运维端点
retrieval.py         ← 检索策略封装
hooks.py             ← 反向阻断通知
```

**规则**：`retrieval.py` 与 `hooks.py` 是跨服务边界模块——前者不依赖 FastAPI，后者只发 HTTP 请求不收请求。route 层只做参数校验和响应格式化。

## 4. 共享包边界

| 包 | 语言 | 用途 | 引用方 |
|---|---|---|---|
| `packages/clinical-contracts` | JavaScript ESM | PoC 状态机 | PoC 代码 |
| `packages/clinical-contracts-py` | Python Pydantic v2 | 正式工程状态机 | workflow-engine / knowledge-orchestrator / fhir-adapter |

**隔离红线**：正式服务只引用 `zhenhu.contracts`（Python），不得 import `poc/` 或 JS 版 contracts。
