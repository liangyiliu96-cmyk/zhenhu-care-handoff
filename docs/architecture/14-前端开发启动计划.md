## 一、技术栈（来自设计文档 §11）

| 层 | 选型 | 理由 |
|------|------|------|
| 构建 | **Vite 6** + React 18 | 设计文档指定，HMR 快，ESBuild 原生 |
| 语言 | **TypeScript strict** | 临床数据要求类型安全 |
| UI 框架 | **MUI v6** | 企业级组件库，Table/DataGrid/ThemeProvider 开箱即用 |
| 样式 | **Tailwind CSS 4** | 与 MUI 互补：MUI 做组件，Tailwind 做排版/间距/响应式 |
| 图表 | **Recharts** | 设计文档指定，React 原生，轻量 |
| 状态 | **Zustand** (客户端) + **TanStack Query v5** (服务端) | 设计文档指定 |
| 路由 | **React Router v7** | 6 页面，路由结构简单 |
| SSE | **fetch + ReadableStream** | 设计文档指定，不用 EventSource（需要 POST + 认证头） |
| 表单 | **React Hook Form + Zod** | 临床表单验证严格 |
| 导出 | **html2canvas + jspdf** | 报表导出 |
| 字体 | Source Serif 4 / IBM Plex Sans / JetBrains Mono | 设计文档指定 |

## 四、高效率开发策略

### 4.1 API 层先行，Mock 对齐

```typescript
// services/patient-service.ts
// 后端开发阶段用 MSW / vite-plugin-mock 拦截
// 后端就绪后去掉 mock，零代码改动

import { apiGet } from '@/core/api-client';
import type { PatientDashboard } from '@/types/patient';

export const getDashboard = (patientId: string) =>
  apiGet<PatientDashboard>(`/inpatient/${patientId}/dashboard`);
```

**Mock 方案**: `vite-plugin-mock` 拦截 `/inpatient/*`，读取 `poc/` 下的 fixture 数据和 `services/inpatient-ward/patient_fixtures.py` 的病例结构。

### 4.2 TanStack Query 封装 — 避免重复样板

```typescript
// hooks/use-patient.ts
export function useDashboard(patientId: string) {
  return useQuery({
    queryKey: ['dashboard', patientId],
    queryFn: () => getDashboard(patientId),
    staleTime: 30_000,        // 30s 内不重新请求
    retry: (count, error) => {
      if (error.status === 404) return false;  // 患者不存在不重试
      return count < 2;                         // 最多重试 2 次
    },
  });
}
```

### 4.3 组件组合而非重复

```
CommandBar.tsx    → 在 DashboardPage 和 DischargePage 共享
KpiCard.tsx       → 在 WorkbenchPage/AdminPage 共享
DiffPanel.tsx     → workbench 的待办队列驱动，在 Dashboard 页面不单独出现
ChatBox.tsx       → 全局共享，通过 mode prop 切换浮/侧/嵌
```

### 4.4 CSS Token 化

```css
/* tailwind.config.ts — 直接用设计文档的 OKLCH tokens */
colors: {
  'surface-page':   'oklch(97% 0.005 250)',

```

不用写 `jss` 或 `sx`，统一 Tailwind className。MUI 只做结构性组件（Table, Modal, Tooltip）。

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| 后端 API 字段与设计文档不一致 | Phase 0 先跑 `api-client.ts` + `GET /whoami` smoke test, 用 `zod` 校验响应 |
| MUI v6 与 Tailwind 冲突 | MUI 的 `sx` prop 不用于布局，只做组件内部样式；Tailwind 做所有布局 |
| SSE 流式渲染性能 | 逐 token append → 每 50ms 批量更新一次 DOM（用 `requestAnimationFrame` 节流） |
| OIDC 回调在本地无法测试 | Phase 0 用 `AUTH_MODE=header` 跳过 SSO，前端不感知 |
| 后端尚未提供 bed/open_beds 字段 | 暂时隐藏 `BedUtilizationRing`，注释标注 "(待后端提供床位字段)" |
| 多个开发者并行时的冲突 | 组件按页面拆分，每人负责不同 Phase，共用 `components/shared/` 时用 PR review |
