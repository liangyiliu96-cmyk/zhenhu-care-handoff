# 临床智能助手体系 — 方案设计 v1.1

**日期：2026-07-18** | **状态：方案设计**

---

## 1. 五种助手能力模式

| 助手 | 用户 | 核心场景 | RAG 层 | 特殊能力 |
|------|------|------|:--:|------|
| **查房助手** | 主治/住院 | 每日查房决策、DDx讨论、治疗方案 | L1-L3,L6,L10 | DB Agent 查病史 |
| **护理助手** | 护士长/护士 | 护理操作指导、交接班、患者教育 | L4,L8,L12,L13 | 护理清单生成 |
| **用药助手** | 医生/药师 | 药物相互作用、剂量调整、禁忌筛查 | L5,L11 | OpenFDA 实时查 |
| **患教助手** | 患者/家属 | 出院须知、用药教育、康复指导 | L9 | 通俗化改写 |
| **中西医协同助手** | 医生 | 中西医双视角评估、出院调养与联用核对 | L1-L3,L5,L6,L15 | 患者上下文 + 引用 |

> 登录身份与助手模式分离。当前登录身份只有 `doctor/nurse`；后端按身份校验可用的 `assistant_mode`，并将 mode 与患者上下文绑定到会话，避免串线。

## 2. 技术架构

```
POST /assistant/chat
  { assistant_mode: "doctor", session_id: "xxx", patient_id: "pat-001", message: "这个心衰患者能出院吗？" }
    ↓
┌──────────────────────────────────────────┐
│              Assistant Engine             │
│                                           │
│  ① 意图识别: 消息→助手类型+查询意图      │
│  ② RAG 检索: 按角色→层映射, 搜知识库     │
│  ③ 上下文组装: 历史对话+患者状态(可选)    │
│  ④ LLM 推理: DeepSeek V4-Pro + RAG 证据  │
│  ⑤ 答案生成: 摘录引用源, 标记置信度       │
└──────────────────────────────────────────┘
    ↓
  { answer: "...", sources: [{layer, topic, text}], confidence: 0.92 }
```

## 3. 会话管理

```
Session {
  assistant_mode: "doctor" | "nurse" | "pharmacist" | "patient" | "integrative"
  owner_id: 已认证 actor_id 或隔离公共客户端 ID
  history: [{role, content}]  ← 最近 10 轮
  patient_id: 可选, 关联到住院患者
  created_at / expires_at
}

存储: Redis (生产) 或 内存 dict (开发)
超时: 30 分钟无活动自动清除
```

## 4. 助手模式→RAG 层映射

| 模式 | 可访问层 | 理由 |
|------|------|------|
| doctor | L1,L2,L3,L5,L6,L7,L10 | 临床决策 + 急症 + 检验 + 用药 |
| nurse | L1,L4,L6,L8,L12,L13,L14 | 护理 + 监测 + 感染 + 营养 |
| pharmacist | L5,L6,L11 | 药物安全 + 检验 + 剂量 |
| patient | L9,L13,L15 | 出院患教 + 营养 + 调养 |
| integrative | L1,L2,L3,L5,L6,L15 | 中西医协同评估 |

## 5. 与现有系统的集成

```
DeepAgent 六组件中的角色:

  RAG           → 按角色过滤层, 检索知识
  LLM           → DeepSeek V4-Pro (强推理)
  DB Agent      → 查房助手可查患者数据
  OpenAPI       → 用药助手实时 FDA 查询
  DeepAgent     → 复用 deep_invoke 三阶段
  Model 路由    → 医生用药→Pro, 患者→Flash
```

## 6. API 设计

```
POST /assistant/chat
  入参: { assistant_mode, session_id?, patient_id?, message }
  出参: { answer, sources, citations, confidence, session_id, assistant_name }

POST /assistant/public/chat/stream
  入参: { session_id?, message } + x-assistant-client
  固定 patient mode，不接收 patient_id，不读取病历

GET  /assistant/session/{session_id}
  查看会话历史

POST /assistant/session/{session_id}/reset
  重置会话

GET  /assistant/sessions?role=doctor&department=心内科
  管理端查看活跃会话
```

## 8. 技术决策

| 决策 | 选项 | 选择 | 理由 |
|------|------|:--:|------|
| 会话存储 | Redis vs 内存 vs SQLite | **内存(先)→Redis(后)** | 减少依赖 |
| 流式输出 | SSE vs WebSocket vs 轮询 | **SSE** | 简单可靠 |
| 意图识别 | LLM vs 规则 → LLM | **规则→LLM** | 先关键词,再用LLM确认 |
| 患者数据接入 | 传 state vs DB Agent 查 | **传 patient_id + 可选 state** | 灵活 |
| 安全 | 角色过滤 + 审计日志 | **两者** | 医疗合规 |
