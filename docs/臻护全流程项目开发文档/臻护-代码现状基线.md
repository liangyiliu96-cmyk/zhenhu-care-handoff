## 四、临床工作流与 AI Agent

- **19 节点 StateGraph**：admission → history_taking → physical_exam → ddx → medication_reconciliation → triage → doctor_confirm → batch_scoring → monitoring → daily_round → nursing → lab_review → discharge → handoff → doctor_review → patient_confirm
- `GRAPH_MODE=classic` 是当前唯一可用模式。
- 出院必须走 6 步：条件评估 → 审核 → 发起 → 签字 → 交接 → 回授。
- AI 输出均为辅助信息/摘要/建议或待确认草稿，不能替代医生/护士法定确认。

## 五、RAG 与证据图谱

- 当前知识基线为 **16 层、385 条**结构化知识；Milvus 已建立可用索引。
- 管理端接口：`GET /admin/rag/dashboard` / `GET /admin/rag/entries` / `GET /admin/rag/preview` / `POST /admin/rag/reindex` / `GET /admin/rag/diagnostics` / `GET /admin/rag/maintenance-log`。

## 六、FHIR 适配与数据互通

- fhir-adapter 独立服务，端口 8300，8 张 FHIR 资源表（Patient/Encounter/Condition/Observation/MedicationRequest/CarePlan/Consent/AuditEvent）。
- **已接入主链路**：住院端提交体征/检验 → BackgroundTasks → fhir_sync → fhir-adapter POST /Observation/Condition。`POST /AuditEvent` 通过 outbox 投递。
- PII 脱敏：Name → 首字+**，Identifier → TOKEN-后4位。
- 每次读写自动 INSERT `fhir_audit_events` 记录。

## 十、存储与部署

- 本地使用 SQLite（`STORAGE_BACKEND=sqlite`）；生产需 MySQL + Alembic 迁移管理。
- RAG 用 Milvus，证据图谱用 Neo4j，Redis 用于会话/运行时缓存。
- 随访联系方式按 Fernet 加密（`CONTACT_ENCRYPTION_KEY`）。
- 后端含 `start.sh` 一键脚本（4 服务 + 健康检查），前端单独 `npm run dev`。
- FHIR_ADAPTER_URL 已配置为 `http://127.0.0.1:8300/fhir`，SKIP_BRIDGE 默认 false。
