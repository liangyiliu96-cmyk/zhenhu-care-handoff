# 二、Agent节点临床逻辑问题（按严重度排列）

## P0 — 患者安全相关，必须立即修复

### P0-1：node_monitoring — 出院批准逻辑完全错误
- **文件**：nodes.py L116-126
- **当前逻辑**：高危需6条体征，低危需3条即批准出院
- **临床问题**：体征记录数量与临床稳定性无关。完全不检查discharge_criteria
- **修正**：必须迭代 `template["discharge_criteria"]` 逐条验证

### P0-2：node_medication_adjust — 单阈值触发调药极危险
- **文件**：nodes.py L277-307
- **当前逻辑**：任一体征突破单个阈值 → 立即生成调药建议
- **临床问题**：单次异常可能是测量误差/疼痛/焦虑。真实调药需综合判断
- **修正**：至少需要连续2-3次异常+医生确认

### P0-3：node_medication_reconciliation — 药物相互作用检测为空
- **文件**：nodes.py L350-400
- **当前逻辑**：冲突检测明确标注"fixture占位"
- **临床问题**：华法林+NSAIDs出血、ACEi+螺内酯高钾——未检测
- **修正**：建立常见药物相互作用规则库（≥50对）

### P0-4：graph.py after_monitoring — 不兼容字段名致3个核心模板失效
- **文件**：graph.py L73-79
- **当前逻辑**：`v_def.get("alert_above")` / `v_def.get("alert_below")`
- **临床影响**：高血压、心衰、糖尿病模板用`alert_high`/`alert_low`，阈值检测完全跳过
- **修正**：统一模板或代码层兼容两种命名

### P0-5：node_triage — 基于模板风险因子"数量"分层而非患者实际数据
- **文件**：nodes.py L87-113
- **当前逻辑**：`risk_factors = len(template.get("risk_factors", []))` — 模板定义数量
- **临床问题**：不吸烟不肥胖的患者因模板定义了5个risk_factors就被判高危
- **修正**：基于实际患者数据逐条匹配模板risk_factors

## P1 — 临床流程缺陷，尽快修复

### P1-1：node_discharge — 未对照discharge_criteria逐条检查
- **文件**：nodes.py L129-184
- 仅判断handoff_items是否存在，不检查出院标准

### P1-2：node_transfer — "高危+3体征→ICU"过于粗糙
- **文件**：nodes.py L328-344
- 高危患者常规测量3次就被建议转ICU
- 应增加疾病特异性转科标准

### P1-3：node_daily_round — 仅计数，无临床内容
- **文件**：nodes.py L255-274
- 仅计数体征/化验/用药数量
- 应按SOAP格式（Subjective/Objective/Assessment/Plan）构建

### P1-4：node_doctor_review — 固定通过前2条驳回第3条
- **文件**：nodes.py L212-241
- Fixture占位，应基于药物-肾功能匹配等真实审核规则

### P1-5：loop.py gen_input — 所有新入院固定加载hypertension
- **文件**：loop.py L30
- `load_template("hypertension")` 硬编码
- 应根据入院诊断动态选择模板

## P2 — 完善性改进

### P2-1：node_lab_review — 仅标记reviewed不做临床解读
- **文件**：nodes.py L310-324
- 应对照正常范围做异常标记和严重度分级

### P2-2：node_patient_confirm — 所有项自动标记"已理解"
- **文件**：nodes.py L244-249
- 应逐项确认+Teach-back评估
