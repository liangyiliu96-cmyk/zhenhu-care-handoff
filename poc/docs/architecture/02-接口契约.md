# PoC 接口契约 v1

基础路径为 `/api/v1`。所有接口均要求登录身份、`X-Request-Id`、请求用途 `X-Use-Purpose: poc-review`，并返回 `case_id` 以便审计关联。

## 统一响应

```json
{
  "request_id": "req_01J...",
  "case_id": "CASE-2026-0715-0042",
  "data": {},
  "error": null
}
```

错误响应：

```json
{
  "request_id": "req_01J...",
  "case_id": "CASE-2026-0715-0042",
  "data": null,
  "error": {
    "code": "CASE_STATE_CONFLICT",
    "message": "当前状态不允许生成任务草稿",
    "details": { "current_state": "review_pending" }
  }
}
```

## 端点

| 方法与路径 | 角色 | 请求摘要 | 成功结果 | 失败语义 |
| --- | --- | --- | --- | --- |
| `POST /cases` | 经治医生 | `mock_case_key`、`idempotency_key` | 创建模拟 `Case` 并返回 `analysing` | `403` 无权限；`409` 幂等冲突 |
| `POST /cases/:caseId/analyse` | 经治医生 | `input_snapshot_version` | 完成确定性规则与模拟检索，进入 `review_pending` | `422` 输入不足；`503` 模拟依赖失败，进入 `failed` |
| `GET /cases/:caseId` | 授权医护 | 无 | 病例、输入摘要、当前状态 | `403` 无病例访问权；`404` 不存在 |
| `GET /cases/:caseId/risks` | 经治医生 | 可选 `status` | 风险项及证据引用 | `409` 未完成分析 |
| `POST /cases/:caseId/risks/:riskId/review` | 经治医生 | `action`、`note`、`decision_version` | 保存人工决定和新的风险项状态 | `409` 重复/过期决定；`422` 无证据引用 |
| `POST /cases/:caseId/task-drafts` | 经治医生 | `idempotency_key` | 所有风险项已处理时生成草稿 | `409` 仍有待审核项 |
| `POST /cases/:caseId/task-drafts/:draftId/simulated-publish` | 经治医生 | `idempotency_key` | 仅写入模拟待办队列 | `409` 草稿字段不完整或状态错误；`409 KNOWLEDGE_CHANGED` 阻断态不可发布 |
| `POST /cases/:caseId/close` | 经治医生 | 无 | 仅 `simulated_published` 可关闭，进入 `closed` | `409` 非 `simulated_published` |
| `POST /cases/:caseId/cancel` | 经治医生 | 无 | 任一非终态取消，进入 `cancelled` | `409` 已为终态 |
| `POST /cases/:caseId/reconcile` | 经治医生 | 无 | `knowledge_changed` 经 reset+重新分析回到 `review_pending` | `409` 非 `knowledge_changed` |
| `POST /cases/:caseId/tasks/:taskId/supplement` | 护士/个案管理师 | `result`、`note` | 补充指派给本人的任务执行信息，任务置 `simulated_supplemented`，状态不变 | `403` 跨角色；`404 TASK_NOT_FOUND` |
| `GET /tasks?mode=simulated` | 护士/个案管理师 | `assignee_role` | 可见模拟待办 | `403` 角色不匹配 |
| `GET /cases/:caseId/audit-events` | 审计员/经治医生 | 分页参数 | 审计事件按时间倒序 | `403` 审计范围不足 |
| `GET /knowledge/audit` | 知识管理员 | 无 | 知识生命周期审计事件 | `403` 无资产读取权限 |
| `POST /demo/reset` | 经治医生 | `scenario`、`interactive` | 重置病例工作流并按场景重跑分析（不重置知识库） | `422` 知识不足（interactive 时返回 failed 概览） |
| `POST /knowledge/documents/import` | 知识管理员 | `title`、`version`、`owner`、有效日期、`source_file_name`、`source_format`、`source_mime`，`.txt/.md` 提交 `content`，`.pdf/.docx` 提交 `file_base64` | 服务端校验扩展名、MIME、5 MiB 大小、签名、SHA-256，先返回 `queued` 任务 | `400` 元数据/MIME/签名/解析/大小错误；`409` 内容哈希重复；`413` 请求体超过 8 MiB |
| `GET /knowledge/import-jobs` | 知识管理员 | 无 | 知识入库任务列表 | `403` 无资产读取权限 |
| `GET /knowledge/import-jobs/:jobId` | 知识管理员 | 无 | 单个入库任务详情 | `403` 无资产读取权限；`404` 任务不存在 |
| `POST /knowledge/import-jobs/:jobId/retry` | 知识管理员 | 无 | 仅重试失败且可重试的入库任务 | `403` 无权限；`409` 状态不允许或失败原因不可重试 |
| `POST /knowledge/runtime/reset` | 知识管理员 | 无 | 清空运行时导入文档、入库任务和知识审计，恢复预置样例 | `403` 无权限 |
| `POST /knowledge/documents/:documentId/transition` | 知识管理员 | `status`（`published`/`expired`/`withdrawn`/`superseded`/`archived`/`review_rejected`） | 按知识版本生命周期切换状态并重建检索索引；`expired`/`withdrawn`/`superseded` 触发反向阻断钩子，将引用该文档的在办病例标为 `knowledge_changed` | `403` 无权限；`409` 非法状态转移（终态不可恢复） |
| `GET /knowledge/documents` | 医生/审计员/知识管理员 | 无 | 文档摘要、有效性和分块数量 | `403` 无资产读取权限 |
| `GET /knowledge/search?q=` | 医生/审计员/知识管理员 | 查询文本 | 仅返回已发布且当前有效的引用 | `400` 空查询 |

## 入库任务状态

`POST /knowledge/documents/import` 立即返回 `queued` 任务；后台异步处理后，任务会变为 `parsing`，最终进入 `review_pending` 或 `failed`。`failed` 任务在 `retryable=true` 时可通过重试接口重新排队。

知识子系统的运行时状态会落到本地文件，服务重启后可恢复；如需回到干净的 PoC 初始样例，可调用 `POST /knowledge/runtime/reset`。

## 状态码与错误码

| HTTP | 错误码 | 处理原则 |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | 请求结构、枚举或必填字段错误 |
| `403` | `ACCESS_DENIED` | 无角色、病例、工具或用途权限；不泄漏病例信息 |
| `404` | `CASE_NOT_FOUND` | 找不到当前授权范围内的模拟病例 |
| `404` | `RISK_NOT_FOUND` | 找不到风险项 |
| `404` | `TASK_NOT_FOUND` | 找不到模拟任务 |
| `409` | `CASE_STATE_CONFLICT` | 状态机前置条件不成立或重复操作 |
| `409` | `KNOWLEDGE_CHANGED` | 所引用知识已变化，已阻断发布/生成草稿，须 `reconcile` |
| `422` | `INSUFFICIENT_EVIDENCE` | 缺少关键字段、证据或已发布知识版本 |
| `503` | `DEPENDENCY_UNAVAILABLE` | 规则/检索/模拟适配器不可用；明确展示降级状态，不生成草稿 |

## 审计约束

每个非 `GET` 请求必须至少产生一条 `AuditEvent`，记录操作人、角色、用途、`case_id`、请求 ID、前后状态、动作、理由、工作流版本和错误码（若有）。
